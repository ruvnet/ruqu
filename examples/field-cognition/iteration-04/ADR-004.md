# ADR 004: Guard MetaHarness development adaptation

## Specification

Execute the real published MetaHarness Darwin numeric optimizer against a frozen development only evaluator. Candidate genomes are untrusted numeric data. They cannot supply scores or see holdout material. Retention means development champion only.

## Pseudocode

Create a fresh work root, validate every proposed genome, evaluate it with fixed development datasets and a hard budget, convert faults to regressed scorecards, independently filter admissible records, require frozen improvement and calibration gates, then atomically retain or revert the development pointer.

## Architecture

Darwin proposes and archives numeric genomes. The campaign wrapper owns evaluator inputs, scoring, admissibility, retention, rollback, digests, and the decision ledger. It does not trust Darwin's winner field because version 0.10.2 may return a regressed record. A work root is never reused because deterministic variant identifiers can collide with an existing archive.

## Refinement

Tests inject thrown errors, nonfinite metrics, timeouts, archive reuse, a regressed high scoring winner, insufficient improvement, calibration regression, and post activation health failure. Two clean Darwin runs must produce identical genomes and scores after timestamps are removed.

## Completion

This iteration performs no holdout evaluation and grants no production promotion. Success means actual package execution, all guards passing, deterministic replay, immutable evidence, and a reversible development champion decision.
